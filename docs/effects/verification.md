# Effect verification

An effect counts as **verified** only when its record says it passed all 12 checks. The count in the README comes from those records, through `scripts/build_catalog.py`. Nothing else can raise it.

## Where the gate runs

`scripts/verify_effects.py` does four things:

1. Installs this repository into a throwaway home with `hermes profile install`.
2. Runs the owner-only toolchain setup there (`npm ci` from the shipped lockfile, plus an existing headless Chrome).
3. Calls the installed profile's own `fx.py verify <effect_id>` for each effect.
4. Copies each record and its stills back next to the effect source.

So the gate exercises the profile as an owner would install it. The same command works for an owner's own effect in `local/effects/`.

Every render goes through the profile launcher (`hf.py render --stage draft`), with all of its gates on.

## Fixture

Synthetic media only, generated by FFmpeg inside the gate:

- a slow gradient with still test bars, a slowly moving skin-tone block, and thin white lines
- a second calm clip with a moving card
- a green-screen clip and a blue-screen clip, each with a drawn subject
- a still frame
- for audio, a synthetic voice-like signal: a 140 Hz buzz with harmonics, a 60 Hz hum, a 6 kHz hiss band, and a syllable envelope

Nothing in the sources flashes, so a flash in a render comes from the effect. Compositions are 320x180, 30 fps, 2 seconds long.

Renders are lossless MP4 (`--crf 0`). Two renders of the same composition give byte-identical decoded frames, so checks 4 and 5 compare frames exactly.

## The 12 checks

| # | Check | How |
| --- | --- | --- |
| 1 | Lint and check pass | `hf.py lint` and `hf.py check` on the default version. `check` includes text contrast. |
| 2 | Renders at default, min and max, faithfully | One render each. Min and max set every parameter to its catalog extreme. The default composition is also rendered with HyperFrames' fast capture switched off (screenshot capture). At 0.2, 0.5, 1.0 and 1.5 s and the probe time, the two must agree within a mean absolute difference of 1.5. This catches an effect the fast path draws wrong, consistently. |
| 3 | Each render differs from the baseline | Mean absolute difference against the same composition without the effect, on the 0 to 255 scale, at the probe time. Default and max must be at least 1.0, or, for a sparse effect such as specks or a thin line, change at least 0.5% of pixels by more than 24 levels (min may be the effect's identity). |
| 4 | The same frame rendered twice is identical | The default composition rendered twice, every frame compared, tolerance 0. |
| 5 | A frame rendered alone matches the same frame in sequence | The frame at 1.0 s of a 1 fps render (one seek from 0) against the 30 fps sequence, tolerance 0. |
| 6 | Animated parameters render as expected | The first animatable parameter is keyframed to min at 0.3 s, default at 1.0 s and max at 1.7 s. Each of those frames is compared with a static render that differs from default only in that parameter. Tolerance 0.75 mean absolute difference. Not applicable when the effect has no animatable parameter. |
| 7 | No network request | Every render runs with outbound network denied by the operating system (`sandbox-exec` on macOS, `unshare --net` on Linux; loopback allowed for the local render server). The project's loaded files are also scanned for remote URLs. |
| 8 | Photosensitivity check recorded | `fx.py flash-check` on the baseline, default, max and animated renders. Fails if the baseline flashes or the default setting flashes. A flash only at max marks the effect limited. See [photosensitivity](../photosensitivity-and-accessibility.md). |
| 9 | Render-cost multiplier measured | Capture seconds with the effect over capture seconds without it. See [performance.md](performance.md). |
| 10 | Reference still and contact sheet | `reference.jpg` (default, at the probe time) and `contact-sheet.jpg` (no effect, min, default, max), made from the synthetic renders. |
| 11 | License and provenance complete | `license`, `provenance`, `implementation_route` and `description` present. A clean-room effect also needs `reference_id`. |
| 12 | Copy detection passes | The effect's own files against the studied project's fingerprints. See [clean-room-process.md](clean-room-process.md). |

Audio effects run the same gate with audio-appropriate checks. Check 3 compares samples. Checks 5, 6 and 10 are not applicable. A 13th check measures the expected change at one frequency: a high-pass must cut the 60 Hz hum, for example.

## Engine findings from building the gate

All of these were observed at HyperFrames v0.8.183 on an Apple M2:

- A `png-sequence` render does not blend shader transitions: the frames hard-cut. MP4 output blends them. The gate renders MP4.
- In one test, a `mov` render showed a dark frame in the middle of a shader transition where MP4 did not.
- The `snapshot` command does not composite shader transitions, so it can't stand in for a render frame. Seek safety is checked with a 1 fps render instead.
- Fast capture (`drawElementImage`) re-projects CSS 3D contexts from content rasterized once, so a video inside a layer with a `perspective()` transform freezes or nearly vanishes. Effects that use 3D transforms set `needs_screenshot_capture`, and `fx.py` then adds a fully transparent `drop-shadow` to the composition root. That filter is HyperFrames' own documented trigger for screenshot capture, and it changes no pixel; the render matched a fast-capture-off render bit for bit. The validator refuses a 3D effect without the flag.
- HyperFrames' `check` reports `text_not_painted` for text whose fill is transparent, and it does not count `-webkit-text-stroke` as paint. An outline-only title fails it, so `outline-reveal` stays unverified. `background-clip: text` is the documented way to mark an intentional transparent fill, but it also clips the element's own background, which would remove a title band.
- HyperFrames prints a capture time of a minute or more as `1m 3.2s`. The gate reads both forms.
- An overlay that carries its own `data-vfx-chain` is a sibling of the target, so it does not inherit custom properties set on the target. Its animated values go on the overlay element (`animate_vars_host` in `effect.json`).
- FFmpeg's `gradients` source picks a random seed unless one is set. Unseeded fixtures differ between runs.
- Inside FFmpeg's `drawbox`, `t` means the box's thickness, not time. Moving fixture shapes go in through `overlay`.

## Re-verifying

After a HyperFrames update, run `python3 scripts/verify_effects.py` again. Then run `python3 scripts/build_catalog.py`, and commit the new records with the update. Any effect that no longer passes drops out of the verified count on its own.
